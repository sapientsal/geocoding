<product_requirements>
The application's core purpose is to enable sales agencies to upload Excel files, geocode addresses, and generate optimized travel routes. Key requirements include: OpenStreetMap Nominatim for geocoding, handling German address formats, and scalability for over 2000 addresses using 2-opt and K-means++. It must support Excel export of geo-sorted routes, retaining original columns across three sheets (Optimized Route, Summary, Distance Analysis). The UI needs file preview, real-time progress feedback, and non-blocking operation. An interactive map is essential for route visualization with numbered markers, intelligent auto-zoom, and detailed popups. Robustness, systematic error fixing, and enhanced frontend error reporting are critical. Specific sorting by street and house number (Street-Based Sorting) was requested, along with a combined Door-to-Door optimization workflow. Reliability for large datasets (e.g., 2741 addresses) without timeouts or API limits is paramount, as demonstrated by the Helmstedt list scenario.
