<product_requirements>
The application is a sales route optimization tool designed to process Excel files containing addresses. It geocodes these addresses using OpenStreetMap and generates an optimized travel route.

Key features implemented:
-   **File Handling:** Supports Excel/CSV uploads with file preview and job history.
-   **Geocoding:** Uses OpenStreetMap Nominatim. Handles German address formats and caches results.
-   **Optimization Logic:** Implements various sorting methods, including Street-Based Sorting (grouping by street, then sorting by house number) and Door-to-Door (nearest neighbor). A critical update ensures that streets are grouped by a combination of street name AND city/town to prevent inefficient routes between different localities.
-   **Map Visualization:** An interactive Leaflet map displays the optimized route with numbered markers. Performance has been optimized for large datasets.
-   **Manual Review:** A UI exists for manually reviewing and correcting addresses that failed to geocode.
-   **Flexible Column Detection:** The system attempts to automatically identify columns for street, house number, postcode, and city, and has been updated to handle variations like Hnr and prioritize Teilort (sub-locality).

The core problem is to provide an efficient, reliable routing tool for sales teams, accommodating various Excel formats and complex German address structures.
</product_requirements>

<key_technical_concepts>
-   **Full-Stack Architecture**: React.js (frontend) and FastAPI (Python backend) with a MongoDB database.
-   **Geocoding**: OpenStreetMap Nominatim API, enhanced with backend caching, batching, and retry logic.
-   **Data Processing**: Pandas for reading and manipulating Excel data.  is also a dependency.
-   **Route Optimization**: Algorithms include Nearest Neighbor, 2-opt, K-means++, and custom street-based sorting logic. Haversine formula is used for distance calculations.
-   **Asynchronous Processing**: Backend jobs (upload, geocoding, optimization) run asynchronously, with the frontend polling for status updates.
</key_technical_concepts>
